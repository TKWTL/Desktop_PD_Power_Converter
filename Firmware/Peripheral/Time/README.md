# 时基(Time API)

> 职责:为驱动、协议栈与调试延时提供统一的 SysTick 时基(µs 计数器 + 1 ms 节拍中断)。

`time_api.c/.h` 在同一个 SysTick 计数器上提供两种粒度,二者机制独立、互不依赖。

## 微秒级:自由运行计数器

- 时钟源 HCLK/8:48 MHz 内核 → 6 MHz 计数器(`STCLK=0`)。
- `STRE=0`,不做自动重装:64 位计数器一直向上计数(低 32 位约 715 s 回绕)。
- `TIME_Ticks32()` / `TIME_Ticks64()` 直接读计数器,`TIME_Micros()` / `TIME_DelayUs()`
  由此推导,**完全不依赖中断**,因此在 ISR 内、临界区附近或任何调度点都可以使用。
- 使用方:USB-PD 的 µs 窗口(`pd_port.c`)、软件 I2C 边沿调度与时钟拉伸超时
  (`soft_i2c.c`)、USART DMA 背压等待(`usart_async.c`)、硬件 I2C 总线恢复脉冲
  (`i2c_api.c`)。

## 毫秒级:1 ms 比较中断自增

- `STE | STIE` 打开计数器与比较中断,`CMP = 6000`(6 MHz × 1 ms);
  `SysTick_Handler()`(`APP/ch32x035_it.c`)转调 `TIME_TickHandler()`。
- 中断内只做三件事:清 `SR` 标志、`s_millis++`、重装下一个比较值——几十条指令。
- **绝对时刻重装**:下一个目标是「上次目标 + 6000 ticks」,而不是「当前计数器 + 6000」。
  即便中断被 USB-PD 等高优先级 ISR 推迟几 µs,tick 的平均周期仍是精确的 1 ms,
  不会累积漂移。
- 若中断被屏蔽超过一个周期,处理器会把漏掉的毫秒补进计数器,并把比较目标推到未来
  (比较是「相等」匹配,目标落在过去将永远不再触发,时基会停摆)。
- 写比较值前还要求与当前计数器保持至少 32 ticks(约 5.3 µs)的余量,避免极端情况下
  「值还没写进去,计数器已经越过目标」。
- `TIME_Millis()` 只读这个 32 位软件计数(约 49.7 天回绕),不再做 64 位除法,
  所以在中断里调用也很便宜(`i2c_api.c` 的状态更新就跑在 ISR 里)。
- 使用方:`coroOS` 的 `THRD_DELAY`、I2C 看门狗、PD 任务时戳、显示与端口遥测周期。

## 中断优先级

- SysTick 抢占优先级 1、子优先级 3(最低):USB-PD 是抢占 0,可以随时打断节拍;
  与 I2C/DMA/USART(抢占 1、子 0~3)同级,不会插队到它们前面。
- 1 ms 节拍同时是空闲唤醒源:`APP_Tasks_Idle()` 的 `WFI` 由它保证至少每 1 ms 醒来一次。

## 注意事项

- `TIME_Init()` 由 `Project/Debug/debug.c` 的 `Delay_Init()` 调用,是最早的初始化之一;
  任何 `TIME_*` 调用都必须发生在它之后。
- 毫秒节拍中断异常时,`TIME_Micros()` / `TIME_DelayUs()` 仍然正确(反之亦然)——
  两者不共享状态。
- 软件 I2C 的兼容性由调度器的空闲钩子保证:传输进行中不进入 `WFI`,保持全速推进
  状态机(见 `Firmware/README.md` 任务总览)。
- ⚠️ 上电需确认:Sleep(`WFI`)期间 SysTick 计数器/中断是否继续工作。若实测发现时间变慢
  (`THRD_DELAY` 变长、超时变长),说明该域被门控,则需改用常规定时器(TIM)做 1 ms
  节拍源,µs 忙等仍可保留在本模块。
